# Transformation Plan: переход к свободному режиму дыхания (hold-to-breathe)

## 1) Цель трансформации

Перевести проект из модели «пресеты и жёсткие фазы» в **единый свободный режим**, где:

- вдох = удержание **левой кнопки мыши**;
- выдох = удержание **правой кнопки мыши**;
- отсутствие удержаний в течение заданного интервала трактуется как потеря фокуса и даёт мягкий аудиосигнал;
- пользователь сам выбирает ритм и может менять его во время сессии;
- система считает метрики (длины вдохов/выдохов и сводные значения) и показывает обратную связь;
- таймер сессии остаётся как единственный явный лимитер (старт/стоп, прошло/осталось).

---

## 2) Что в текущей версии неудобно (и почему это нужно убрать)

По текущей реализации в `index.html` видно, что UX построен вокруг:

1. фиксированных пресетов дыхания (4-7, box и т.д.);
2. шагов цикла (`inhale`/`exhale`/`hold`) с таймерами;
3. промежуточного `window`-окна подтверждения;
4. логики «следовать программе», а не телу/самочувствию.

Проблема этого подхода: он навязывает ритм и когнитивно нагружает пользователя, если естественный ритм отличается от запрограммированного. Для расслабления это контрпродуктивно.

---

## 3) Целевой UX (новая версия)

### Основной сценарий

1. Пользователь выбирает длительность сессии (например, 3/5/10/15/20 минут или custom).
2. Нажимает «Старт».
3. Дышит свободно:
   - держит ЛКМ во время вдоха;
   - держит ПКМ во время выдоха.
4. Если долго нет активного удержания — звучит мягкий alert.
5. По ходу сессии на экране отображаются:
   - текущее состояние (вдох / выдох / пауза);
   - прошло / осталось;
   - средняя длина вдоха / выдоха;
   - количество завершённых вдохов/выдохов.
6. По завершении — краткая сводка сессии.

### Визуализация (без over-engineering)

- Круг остаётся как основной визуальный объект.
- Простая анимация:
  - ЛКМ удерживается → круг плавно растёт до верхней границы;
  - ПКМ удерживается → круг плавно уменьшается до нижней границы;
  - ничего не удерживается → нейтральное состояние.
- Без сложного расчёта «идеального» размера/фазы.

---

## 4) Объём изменений по коду

Поскольку текущая версия находится в одном `index.html`, трансформация будет включать **упрощение и частичную замену логики**:

### Удаляем/деактивируем

- модель `BREATH_MODES` и весь UI выбора режимов;
- пошаговый движок `runCurrentStep` и `window`-фазы;
- расчёты циклов, привязанные к preset-режимам;
- фазовые звуки, завязанные на предопределённые шаги.

### Добавляем

- единый state-machine «input-driven breathing»;
- фиксацию событий удержания:
  - start inhale / end inhale,
  - start exhale / end exhale;
- расчёт метрик по фактическим удержаниям;
- таймер сессии (elapsed/remaining) как центральный механизм;
- детектор отвлечения по таймауту без активности;
- (опциональный этап) поддержка клавиш как альтернативного ввода.

---

## 5) Предлагаемая новая модель состояния

```text
SessionState:
- running: boolean
- startedAtMs: number | null
- endsAtMs: number | null
- durationMs: number

InputState:
- inhaleActive: boolean      // ЛКМ
- exhaleActive: boolean      // ПКМ
- inhaleStartedAtMs: number | null
- exhaleStartedAtMs: number | null
- lastActivityAtMs: number | null

BreathStats:
- inhaleDurationsMs: number[]
- exhaleDurationsMs: number[]
- inhaleCount: number
- exhaleCount: number
- avgInhaleMs: number
- avgExhaleMs: number
- longestInhaleMs: number
- longestExhaleMs: number

AlertState:
- inactivityThresholdMs: number
- alertActive: boolean
```

### Принципы

- В один момент активен только один тип дыхания (если пересечение событий — приоритет последнему событию).
- В статистику попадают только удержания длиннее минимального порога (например, 120–200 мс), чтобы отсеять случайные клики.
- Наличие пауз между вдохом и выдохом допустимо и не считается ошибкой.

## 6) План реализации (по этапам)

## Этап 1. Подготовка UI-скелета

- Упростить панель:
  - удалить блок «Режим дыхания»;
  - оставить «Длительность сессии» + «Старт/Стоп» + звук;
  - добавить блок метрик (средние длины, количество фаз, текущее состояние);
  - добавить «Прошло / Осталось» в явном виде.
- Обновить подсказки/ARIA под новый режим удержания ЛКМ/ПКМ.

**Результат:** интерфейс соответствует единому режиму, но может ещё не иметь полной логики.

## Этап 2. Новый input-driven движок

- Реализовать обработку `pointerdown/pointerup`:
  - ЛКМ = inhale start/end;
  - ПКМ = exhale start/end (с отключением context menu).
- Ввести единый `tick` (через `requestAnimationFrame` или `setInterval`) для:
  - elapsed/remaining;
  - проверки inactivity;
  - обновления виджета текущего состояния.
- Корректно обрабатывать `pointercancel`, `blur`, `visibilitychange`.

**Результат:** сессия управляется только действиями пользователя.

## Этап 3. Метрики дыхания

- На завершении каждого удержания сохранять длительность в соответствующий массив.
- Считать и рендерить:
  - среднюю длину вдоха;
  - среднюю длину выдоха;
  - count вдохов/выдохов;
  - (опционально) отношение выдох/вдох.
- Показать мини-сводку после завершения сессии.

**Результат:** пользователь видит обратную связь по фактической практике.

## Этап 4. Детектор отвлечения + аудиосигнал

- Обновлять `lastActivityAtMs` на каждом start/end inhale/exhale.
- Если `now - lastActivityAtMs > inactivityThresholdMs` и сессия активна:
  - включать мягкий alert-тон;
  - в UI показывать статус «Похоже, вы отвлеклись».
- При любой новой активности — сразу гасить сигнал.

**Результат:** приложение мягко возвращает внимание без жёсткого навязывания ритма.

## Этап 5. Полировка и стабильность

- Проверить конфликтные сценарии (зажаты обе кнопки, смена кнопки без отпускания, выход курсора).
- Уточнить thresholds и визуальные переходы.
- Очистить неиспользуемый код старой архитектуры.

**Результат:** простой и поддерживаемый код без «наследия режимов».

## Этап 6 (опционально, после валидации): клавиатурный ввод

- Добавить карту управления:
  - `ArrowLeft` = вдох,
  - `ArrowDown` (или `ArrowRight`) = выдох.
- Сделать опцию переключения «мышь / клавиатура / оба».

**Результат:** доступность и комфорт для пользователей без мыши.

---

## 7) Что сохранить из текущей версии

- базовую визуальную стилистику (тёмная тема, центральный круг);
- механизм мягкого аудио-алерта (перенести и упростить);
- пресеты длительности сессии (как таймер, а не как ритм);
- кнопку Start/Reset (переименовать в Start/Stop, если логичнее).

---

## 8) Риски и как их закрыть

1. **Конфликт системных событий ПКМ / context menu**
   - Явно подавлять `contextmenu`; тестировать в Chromium/Safari/Firefox.

2. **Потеря pointer-событий при выходе за пределы окна**
   - Обрабатывать `pointercancel`, `blur`, `visibilitychange`; форс-останавливать активные удержания.

3. **Шум в статистике из-за случайных кликов**
   - Минимальный валидный порог длительности удержания.

4. **Аудио-ограничения браузера (autoplay policy)**
   - Инициализация аудиоконтекста только после явного пользовательского действия (Start/первый hold).

---

## 9) Критерии готовности (Definition of Done)

- Нет выбора режимов дыхания в UI и коде.
- Сессия запускается по времени и управляется только удержаниями.
- ЛКМ/ПКМ корректно фиксируют вдох/выдох.
- Метрики вдоха/выдоха отображаются и адекватно обновляются.
- Inactivity alert срабатывает и отключается по активности.
- После завершения сессии пользователь получает понятную сводку.
- Код остаётся внятным, без сложной математики и лишних абстракций.
